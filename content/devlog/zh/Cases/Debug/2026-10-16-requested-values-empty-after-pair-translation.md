# 成对平移后要求值为空

把两个焊印沿 +Y 各移 1 mm 的 run 成功了，但结果页上所有要求值都是空的。==B1 请求格式给两个平移各写了一遍要求句。▒▒▒▒▒▒▒▒ 只接受恰好一句匹配，于是 `requested` 字段（要求值）变成 null，独立偏差断言也就跳过了。==

这个 run 看起来还是对的，四个 Y 测量值都是 +1 mm，但本该发现错误测量值的那项检查没有执行。

修复在 [[zh/Glossary/PR|PR]] ▒▒▒▒：同轴、同向、同距离的平移，合并成一句要求。

## 现象

在 structure 工作台（应用里包着 ▒▒▒▒▒▒▒▒ 引擎的 UI）做本地集成验收时发现：

| 项 | 值 |
| --- | --- |
| 发布版本 | `▒▒▒▒▒▒▒▒▒▒▒▒` |
| ▒▒▒▒▒▒▒▒ | `▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒` |
| Planner | 真实的 Qwen3.8-27B |
| 设置 | 生成式编辑关闭，并发 1 |
| 请求 | 修改定义里两行，每行 +Y 1 mm |
| Run | 成功，113.24 s |
| 结果页 | 修改结果在前，装配复检通过 |
| 测量值 | 四个焊印 Y 测量值，都是 +1 mm |
| 要求值 | 全部为空 |

修改定义是工作台里描述编辑的结构化表单，每个零件和动作占一行。UI 部分都通过了：缺动作时不能提交，撤销和重做能还原同样的请求。验收报告把要求值为空记为 **P1**，属于协议回归，也就是工作台和 ▒▒▒▒▒▒▒▒ 之间的请求契约断了。

## 排查过程

原始简报只记了原因和修复，没记中间步骤。之前有过一次记录在案的类似现象。10/14 的 replay 评审里（见 ▒▒▒▒▒▒▒▒），候选 8 是组目标，要求值一栏也是空的，页面上写着「多目标请求暂不提取要求值」。那次评审把它列为 ▒▒▒▒▒▒▒▒ 侧的问题，指向 `▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒` 中 `requested_translation` 的实现。简报没有说那次是不是同一个原因。

## 根因

![两次序列化 +Y 1 mm 要求使 requested 为空，尽管四个实测变化都符合要求，偏差检查仍被跳过。](../../Diagrams/2026-10-16-requested-values-empty-after-pair-translation.data-flow.svg)

1. 两行按 B1 请求格式序列化。B1 是提交 run 时用的文本格式，它给每个平移各生成一次要求句，所以请求里有两句。
2. ▒▒▒▒▒▒▒▒ 从匹配的要求句里取要求值，而且只接受一处匹配。
3. 匹配到两处，它就把 `requested` 设成 null。
4. **独立偏差断言** 拿每个测量出的变化量和对应的要求值比较。没有要求值就没东西可比，于是跳过了。

结果页上于是出现了正确的测量值，旁边是空的要求值。偏差检查没有执行，所以既没报通过，也没报失败。

## 修复

▒▒▒▒ 的标题是「合并同向成对平移要求以恢复独立复测」，以 `▒▒▒▒▒▒▒▒▒▒▒▒` 合并。

| 情况 | ▒▒▒▒ 之后的请求文本 |
| --- | --- |
| 单轴平移，同轴、同向、同距离 | 合并成一句要求 |
| 混合向量 | 保留原文本 |
| 同一零件上的连续动作 | 保留原文本 |

43 条原有 replay 预期，一条都不用改。

验证用的 run `▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒` 在 116.99 s 内成功。四个要求值都回来了，偏差都是 0，单位 mm。

| 测量项 | ▒▒▒▒ 之后的要求值（mm） |
| --- | --- |
| 焊印 1 ymin | -13.999984664000014 |
| 焊印 1 ymax | -8.999984664199985 |
| 焊印 2 ymin | 11.0000153358 |
| 焊印 2 ymax | 16.0000153358 |

| 检查 | 结果 |
| --- | --- |
| Tier 1 | 3 个文件 / 153 个测试通过；typecheck、格式和 diff 检查通过 |
| Replay 预期 | 原有 43 条，修改 0 条 |
| Pre-review | 第一轮出现 `BLOCKERS=1` 并已修复，最终 `BLOCKERS=0` |

## 遗留问题

- **旧 B1 草稿。** 恢复旧的结构化 B1 草稿时会退回解析路径，这条路径可能丢掉 `inst` 身份和尺寸动作。风险中等，没放进 ▒▒▒▒，因为恢复逻辑超出了序列化修复的范围。
- **混合向量。** 混合向量之类的请求，目前的 ▒▒▒▒▒▒▒▒ 仍然没法独立复测。引擎冻结到 2026-10-31，之后再决定这类请求怎么验收。

## 经验和技巧

- **跳过的断言看起来像通过。** 测量值正确、要求值为空，说明检查根本没跑。缺少期望值要当作检查失败，不能当作没事可报。
- **一方只接受恰好一处匹配，另一方就必须恰好输出一处。** 对要求唯一匹配的解析器来说，两句一样的话会让值读不出来。
- **修序列化器，范围和 bug 一样窄。** 只合并同轴、同向、同距离的平移，43 条原有 replay 预期都没变。
- **验收时要看要求值一栏，不能只看测量值。** 要求值为空的「成功」run，对几何结果没有任何独立检查。
