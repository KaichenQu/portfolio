# 成对平移后要求值为空

把两个焊印沿 +Y 各移 1 mm 的 run 跑通了，结果页上所有要求值却都是空的。==B1 请求格式给两条平移各写了一遍要求句；▒▒▒▒▒▒▒▒ 只认恰好一句匹配，于是 `requested` 字段（要求值）变成 null，独立偏差断言直接跳过。==

这个 run 看着还是对的，四个 Y 测量值都是 +1 mm，但本该抓出错测量的检查根本没跑。

修复在 [[zh/Glossary/PR|PR]] ▒▒▒▒：同轴、同向、同距离的平移合并成一句要求。

## 现象

在 structure 工作台（应用里包着 ▒▒▒▒▒▒▒▒ 引擎的 UI）做本地集成验收时发现：

| 项 | 值 |
| --- | --- |
| 发布版本 | `▒▒▒▒▒▒▒▒▒▒▒▒` |
| ▒▒▒▒▒▒▒▒ | `▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒` |
| Planner | 真实的 Qwen3.8-27B |
| 设置 | 生成式编辑关闭，并发 1 |
| 请求 | 修改定义里两行，每行 +Y 1 mm |
| Run | 成功，113.24 s |
| 结果页 | 修改结果在前，装配复检通过 |
| 测量值 | 四个焊印 Y 测量值，都是 +1 mm |
| 要求值 | 全部为空 |

修改定义是工作台里描述编辑的结构化表单，每个零件和动作占一行。UI 侧检查全过：缺动作不能提交，撤销和重做能还原原请求。验收报告把要求值为空记成 **P1**，属协议回归，也就是工作台和 ▒▒▒▒▒▒▒▒ 之间的请求契约断了。

## 排查过程

原始简报只记了原因和修法，没记中间步骤。此前记录过一次类似现象：10/14 的 replay 评审里（见 ▒▒▒▒▒▒▒▒），候选 8 是组目标，要求值一栏也空着，页面写「多目标请求暂不提取要求值」。当时列成 ▒▒▒▒▒▒▒▒ 侧问题，指向 `▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒` 里的 `requested_translation`。简报没写那次是不是同一原因。

## 根因

![两次序列化 +Y 1 mm 要求使 requested 为空，尽管四个实测变化都符合要求，偏差检查仍被跳过。](../../Diagrams/2026-10-16-requested-values-empty-after-pair-translation.data-flow.svg)

1. 两行按 B1 请求格式序列化。B1 是提交 run 用的文本格式，给每个平移各生成一句要求，请求里于是有两句。
2. ▒▒▒▒▒▒▒▒ 从匹配的要求句里提取要求值，且只接受一处匹配。
3. 匹配到两处，它就把 `requested` 置为 null。
4. **独立偏差断言**拿实测变化量和对应要求值比对。没有要求值就没法比，断言直接跳过。

结果页上于是出现正确的测量值和空的要求值。偏差检查没跑，既没报通过也没报失败。

## 修复

▒▒▒▒ 标题为「合并同向成对平移要求以恢复独立复测」，合并提交 `▒▒▒▒▒▒▒▒▒▒▒▒`。

| 情况 | ▒▒▒▒ 之后的请求文本 |
| --- | --- |
| 单轴平移，同轴、同向、同距离 | 合并成一句要求 |
| 混合向量 | 保留原文本 |
| 同一零件上的连续动作 | 保留原文本 |

43 条原有 replay 预期，一条都不用改。

验证 run `▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒` 在 116.99 s 内跑通。四个要求值全回来了，偏差都是 0，单位 mm。

## 遗留问题

- **旧 B1 草稿。** 恢复旧的结构化 B1 草稿时会退回解析路径，可能丢掉 `inst` 身份和尺寸动作。风险中等，没有放进 ▒▒▒▒，因为恢复逻辑超出了序列化修复范围。
- **混合向量。** 混合向量这类请求，现在的 ▒▒▒▒▒▒▒▒ 依然没法独立复测。引擎冻结到 2026-10-31，之后再定怎么验收。

## 经验和技巧

- **跳过的断言看着像通过。** 测量值对、要求值空，说明检查根本没跑。缺期望值要按检查失败处理，别当成没事可报。
- **一方只认恰好一处匹配，另一方就必须恰好输出一处。** 对要求唯一匹配的解析器，两句重复的话只会让值读不出来。
- **修序列化器，改动面跟 bug 一样窄。** 只合并同轴、同向、同距离的平移，43 条原有 replay 预期一个没动。
- **验收时要看要求值一栏，别只盯测量值。** 要求值为空的「成功」run，对几何结果没有任何独立核验。
